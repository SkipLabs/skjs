Awaited is unsound on object types

Example 1 (object types are open). Accepted by tsc --strict; Node gives "hi".

function asRecord(x: { n: number }): { n: number } { return x; }
const t = { n: 1, then(resolve: (v: string) => void) { resolve("hi"); } };
const v = await asRecord(t); // TS: { n: number } Node: "hi"

Example 2 (resolution is not idempotent). Accepted by tsc --strict; Node gives 42.

const obj = { value: 1 };
const p: Promise<{ value: number }> = Promise.resolve(obj);
Object.assign(obj, { then: (r: (x: number) => void) => r(42) });
const first = await p;     // TS: { value: number } Node: obj
const second = await first; // TS: { value: number } Node: 42

Calcagno · Typing Promise Resolution · observed with tsc 7.0.2 and Node

Example 1 is width subtyping: Awaited of a type with no declared then is the type itself, but the runtime value carries one. Example 2 breaks Awaited<Awaited<T>> = Awaited<T>: a value resolution already produced resolves the promise again with a different result.
