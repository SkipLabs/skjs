# SKJS Binary Distribution

Pre-built SKJS binaries are published as **GitHub Releases** on every `v*` tag push, by the workflow at [.github/workflows/release.yml](../.github/workflows/release.yml).

Because `SkipLabs/skjs` is a private repo, releases inherit private visibility — every release page and asset URL requires a GitHub account with read access to the repo.

## What gets published

For each release at `vX.Y.Z`:

| Asset | Description |
| --- | --- |
| `skjs_vX.Y.Z_linux_amd64` | The release binary (x86-64) |
| `skjs_vX.Y.Z_linux_amd64.json` | Build metadata for the amd64 binary (commit, run id, timestamp, workflow URL) |
| `skjs_vX.Y.Z_linux_arm64` | The release binary (arm64) |
| `skjs_vX.Y.Z_linux_arm64.json` | Build metadata for the arm64 binary |
| `import-stubs.tgz` | Stub type declarations bundled with the release |
| `SHA256SUMS` | Checksums covering all of the files above |

GitHub also auto-attaches `Source code (zip)` and `Source code (tar.gz)` snapshots of the tagged commit.

Release notes are auto-generated by GitHub from the PR titles merged since the previous tag.

## Downloading a release

You need a GitHub token (PAT or fine-grained token) with `contents: read` on `SkipLabs/skjs`. If the SkipLabs org has SAML SSO enabled, the token must be SSO-authorized for it.

### `gh` CLI

```bash
# Latest release
gh release download --repo SkipLabs/skjs --pattern 'skjs_*_linux_amd64'

# Specific tag
gh release download v1.2.3 --repo SkipLabs/skjs --pattern '*'
```

### `curl`

```bash
# Resolve the asset URL once, then stream it
curl -L \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Accept: application/octet-stream" \
  -o skjs \
  "https://api.github.com/repos/SkipLabs/skjs/releases/tags/v1.2.3"
```

(For `latest`, replace `tags/v1.2.3` with `latest`.)

### Verifying

`SHA256SUMS` lists every release asset, so `-c` reports the ones you didn't download as missing — use `--ignore-missing` to check only what you have:

```bash
sha256sum --ignore-missing -c SHA256SUMS
```

## Using a downloaded binary

Make the binary executable and unpack the type stubs next to it:

```bash
chmod +x skjs_*_linux_amd64
mkdir import-stubs && tar -xzf import-stubs.tgz -C import-stubs
./skjs_*_linux_amd64 check --import-stubs ./import-stubs path/to/file.ts
```

The binary is self-contained except for these stubs, so `skjs check` needs `--import-stubs <dir>`. The `skjs run` subcommand additionally requires [Bun](https://bun.sh) on `PATH`.

## Local builds

For day-to-day development you don't need a release — just build from source:

```bash
# Dev binary
skargo build

# Release binary (matches what the workflow produces)
skargo build --release --bin skjs
```

The binary lands at `target/host/{dev,release}/skjs`. The runtime stamps `--version` with the version from `Skargo.toml` plus the short git hash (or `GITHUB_SHA[:7]` when running in GitHub Actions).

## Platform support

Currently published: **linux/amd64** and **linux/arm64**.

Adding macOS (or other targets) means extending the matrix in [.github/workflows/release.yml](../.github/workflows/release.yml) and ensuring the Skip toolchain image supports the target.

## Troubleshooting

### "Not Found" / 404 when downloading

Token doesn't have access to the repo, or SAML SSO isn't authorized for it. Test with `gh auth status` and `gh api repos/SkipLabs/skjs`.

### `--version` prints `skjs <ver> ()` (empty hash)

Both `git rev-parse` and `GITHUB_SHA` were unavailable at build time. Inside containers this is usually a `safe.directory` issue; outside CI, `git` likely isn't on `PATH`.
